# 수익화 계약 검토

광고 수익화 계약서(Word·PDF)를 올리면 AI가 다음 작업을 해 주는 팀 공용 웹 툴이에요.
- 조항 분석
- 버전별 수정 내역과 코멘트 정리
- Lexus 검토 요청 · flex 품의서 문안 작성
- 노션 페이지 생성

claude.ai **아티팩트**(claude.ai 안에서 열리는 웹페이지) 한 장으로 동작해요. 그래서 따로 서버를 빌리거나 API 키를 발급받을 필요가 없어요.

---

## 이 툴로 할 수 있는 일

### 업무 흐름별

| 업무 단계 | 툴이 해 주는 일 |
| --- | --- |
| 업체에게 계약서 수령 | Word·PDF를 올리면 영문 전문을 한국어로 번역해요. Word 변경 추적과 코멘트, PDF 주석을 모두 읽어요 |
| 수익화팀 1차 검토 | 팀 검토 기준표에 맞춰 조항마다 **유리 · 주의 · 불리 · 정보**로 판정해요. 정산 조항과 독소 조항은 원문 전문으로 바로 이동해서 확인할 수 있어요 |
| Lexus 검토 요청 | Lexus 요청 서식(계약명, 계약상대방, 계약조건, 요청사항, 첨부파일)에 맞춘 문안을 복사 버튼 하나로 가져가요 |
| 법무팀 ↔ 업체 수정 핑퐁 | 새 버전을 올릴 때마다 무엇이 바뀌었는지 수정 전후와 한글 번역으로 비교해요. 업체 회신을 Lexus 댓글로 공유할 문안도 만들어요 |
| flex 계약 품의서 상신 | 품의서 서식(문서 이름, 거래상대방, 계약 내용, 계약일, 서명인)에 맞춘 문안을 만들어요 |
| 노션 등록 | '수익화 체결 계약서' DB와 '파트너 DB'에 업체 페이지를 만들고 서로 연결해요. 정산 조건(여신일, R/S, 정산기준 등)은 계약서 내용으로 채워요 |

### 화면 메뉴

| 메뉴 | 내용 |
| --- | --- |
| 현재 계약서 조항 분석 | 기준표 대비 판정 결과. 유리·주의·불리·정보로 걸러 볼 수 있고, 조항 번호를 누르면 원문과 번역 전문의 해당 위치로 이동해요 |
| 계약서 수정 히스토리 | 버전 사이에 바뀐 문단을 수정 전후로 나란히 보여주고 한글 번역을 붙여요 |
| 문서 내 코멘트 히스토리 | 코멘트를 조항별 쟁점으로 묶어서 맥락, 실제 본문 변화, 우리 회사에 불리해졌는지를 보여줘요. 상대방 내부 메모로 보이는 코멘트는 따로 표시해요 |
| 복붙 텍스트 | Lexus 검토 요청, Lexus 댓글, flex 품의서 문안. 노란 칸은 계약서에 정보가 없어서 직접 채워야 하는 부분이에요 |
| 노션 DB 생성 | 노션 두 DB에 들어갈 내용을 미리 보고 고친 뒤 생성 버튼으로 만들어요. 날인본 파일은 만든 페이지에 직접 첨부해요 |

계약 건, 버전, 분석 결과는 팀 공유 저장소에 쌓여요. 팀원 누구나 같은 히스토리를 볼 수 있어요.

---

## 먼저 알아둘 점: claude.ai 안에서만 동작해요

이 툴의 저장, AI 분석, 노션 연동은 모두 **claude.ai가 페이지에 직접 제공하는 기능**이에요. 그래서 소스를 받아서 PC에서 HTML 파일을 그냥 열면 "claude.ai에서 열어야 저장할 수 있어요"라는 안내만 보여요.

이 문서에서 말하는 "설치"는 다음 순서를 뜻해요.

**PC에 소스 받기 → 한 파일로 합치기(빌드) → claude.ai에 아티팩트로 올리기**

---

## 내 상황에 맞는 방법 고르기

| 상황 | 할 일 |
| --- | --- |
| **A. 지금 쓰고 있는 사이트를 그대로 쓰고 싶어요** | 설치할 것이 없어요. 사이트 소유자에게 **기여자** 권한을 요청하세요. → [5. claude.ai에서 추가로 할 일](#5-claudeai에서-추가로-할-일)만 보면 돼요 |
| **B. 기존 사이트의 기능을 고치고 싶어요** (주소와 히스토리 유지) | 사이트의 **소유자나 편집자** 권한이 필요해요. → 1~4단계를 따라 하고, 4단계에서 'B'를 고르세요 |
| **C. 기존 사이트를 더 이상 열 수 없어요** (새로 만들기) | 1~5단계를 모두 따라 하고, 4단계에서 'C'를 고르세요 |

## 1. 준비물

| 준비물 | 용도 | 확인 방법 |
| --- | --- | --- |
| 회사 claude.ai 계정 (Team·Enterprise 플랜) | 사이트 사용·공유 | claude.ai 로그인 |
| **Claude Code** | 빌드한 파일을 claude.ai 아티팩트로 올리기 | 설치 안내: https://claude.com/claude-code |
| `config.local.js` (사내 설정 파일) | 회사명, 노션 DB ID, 내부 검토 기준표 | **저장소에 없어요.** 이전 담당자나 팀 공유 드라이브에서 받으세요 |
| git (선택) | 소스를 받고 변경 이력 관리 | 터미널에서 `git --version` |

> `config.local.js`에는 내부 협상 기준이 들어 있어요. 공개 저장소나 메신저 공개 채널에 올리지 마세요.

## 2. 소스 코드 받기

둘 중 편한 방법을 쓰세요.

**방법 1. ZIP으로 받기 (git 없이)**
1. https://github.com/SC-Jade/contract-review-tool 을 열어요.
2. 초록색 **Code** 버튼 → **Download ZIP**을 눌러요.
3. 받은 ZIP을 원하는 폴더에 풀어요. 예: `문서/contract-review-tool`

**방법 2. git으로 받기**
```sh
git clone https://github.com/SC-Jade/contract-review-tool.git
cd contract-review-tool
```

## 3. 사내 설정 넣고 빌드하기

1. 받은 `config.local.js`를 소스 폴더의 `app` 폴더 안에 넣어요.
   ```
   contract-review-tool/
     app/
       config.local.js   ← 여기
       app.js
       ...
   ```
2. 터미널에서 소스 폴더로 이동해서 빌드해요.
   ```sh
   sh app/build.sh
   ```
3. `built with config.local.js`가 나오면 성공이에요. `app/contract-review.html`이 만들어져요.
   - `built with config.example.js`가 나오면 설정 파일이 `app` 폴더에 없는 거예요. 이 상태로 올리면 노션 연동과 내부 기준표가 동작하지 않아요.

> 터미널이 익숙하지 않다면 소스 폴더에서 Claude Code를 열고 "app/build.sh로 빌드해줘"라고 요청해도 돼요.

## 4. claude.ai에 올리기

소스 폴더에서 Claude Code를 열고, 상황에 맞는 요청을 그대로 붙여 넣으세요.

**B. 기존 사이트 고치기** (주소, 공유 상태, 저장된 히스토리가 그대로 유지돼요)
```
app/contract-review.html을 기존 아티팩트 <기존 사이트 주소>에 업데이트해서 공개해줘.
capabilities는 기존 것을 그대로 유지해줘.
```

**C. 새 사이트 만들기**
```
app/contract-review.html을 새 아티팩트로 공개해줘. capabilities는 아래와 같이 선언해줘.
{
  "db": {},
  "user": { "scopes": ["profile"] },
  "sample": {},
  "mcp": { "servers": [{ "server": "Notion", "tools": ["notion-create-pages", "notion-search", "notion-update-page"] }] }
}
```

각 capability의 뜻은 다음과 같아요.

| capability | 뜻 |
| --- | --- |
| `db` | 팀 공유 저장소 |
| `user` | 화면에 작성자 이름 표시 |
| `sample` | AI 분석 |
| `mcp` | 노션 페이지 만들기·검색·연결 |

> **C를 고르면 히스토리가 비어 있어요.** 이전 계약 건과 분석 결과는 기존 사이트의 저장소에 남아 있어요. 기존 사이트를 아직 열 수 있다면 Claude Code에 "기존 아티팩트 <주소>의 db 데이터를 새 아티팩트 <주소>로 옮겨줘"라고 요청해서 옮길 수 있어요.

## 5. claude.ai에서 추가로 할 일

새로 만들었든 기존 사이트를 쓰든, 아래가 갖춰져야 지금과 똑같이 쓸 수 있어요.

### 사이트 소유자가 할 일 (한 번만)

| 할 일 | 방법 |
| --- | --- |
| 팀원 공유 | 사이트 오른쪽 위 **공유** → 팀원 추가 → 권한 **기여자**. 댓글 작성자나 뷰어는 업로드·분석·노션 생성을 할 수 없어요 |
| 후임 관리자 지정 | 최소 1명은 **소유자**로 지정해 두세요. 내가 퇴사해도 공유와 수정을 이어갈 수 있어요 |
| 검토 기준표 확인 | 사이트의 **기준표 편집**을 열어 내용을 확인하고 **저장**해요. 새 사이트(C)는 저장하기 전까지 `config.local.js`의 기본값을 써요 |

### 팀원 각자 할 일 (처음 한 번)

| 할 일 | 방법 |
| --- | --- |
| Notion 커넥터 연결 | claude.ai **설정 → 커넥터**에서 Notion을 연결해요. 노션 DB 생성 버튼을 쓰려면 꼭 필요해요 |
| 노션 DB 쓰기 권한 | 노션에서 '수익화 체결 계약서'와 '파트너 DB'에 페이지를 추가할 수 있는지 확인해요 |
| 허용 창 승인 | 처음 AI 분석을 누를 때 **Claude 사용 허용**, 처음 노션 생성을 누를 때 **Notion 허용** 창이 떠요. 둘 다 허용해요. 실수로 거절했다면 페이지를 새로 고친 뒤 다시 누르면 돼요 |

### 알아둘 점

- AI 분석 사용량은 **분석 버튼을 누른 사람의 claude.ai 계정**에서 차감돼요.
- 계약서 한 버전을 분석하는 데 보통 3~10분 걸려요. 분석 중에 창을 닫으면 멈추고, 다시 열어서 **이어서 분석하기**를 누르면 돼요.
- 계약서 파일은 노션 업로드 제한 때문에 노션 페이지에 직접 첨부해야 해요.

## 소스를 고친 뒤 GitHub에 반영하기

1. 소스(`app/app.js` 등)를 고쳐요. Claude Code에 원하는 변경을 요청해도 돼요.
2. `sh app/build.sh`로 다시 빌드하고, [4단계 B](#4-claudeai에-올리기)로 사이트에 반영해요.
3. GitHub에 올려요.
   ```sh
   git add -A
   git commit -m "변경 내용 요약"
   git push
   ```
   `config.local.js`와 빌드된 `contract-review.html`, 계약서 파일(`.docx`, `.pdf`)은 `.gitignore`에 들어 있어서 올라가지 않아요.

## 개발자용 참고

### 폴더 구조
```
app/
  shell.html          화면 구성과 스타일
  parse-core.js       Word·PDF 파싱, 버전 비교
  app.js              화면 동작, AI 분석 순서, 노션 연동
  config.example.js   설정 예시 (config.local.js의 형식)
  build.sh            위 파일을 합쳐 app/contract-review.html 한 장을 만들어요
tests/
  smoke.js            가짜 저장소·AI·노션으로 전체 흐름을 자동 점검해요
  test-docx.js        Word 파일 폴더를 버전 순서대로 파싱해요
  test-pdf.js         PDF 파싱 결과를 출력해요
  make-pdf.js         Word로 주석이 달린 테스트 PDF를 만들어요
```

### 설정 항목 (`config.local.js`)

| 항목 | 내용 |
| --- | --- |
| `COMPANY` | 우리 회사 이름. 문서 작성자 이름으로 우리 쪽을 알아보는 패턴도 포함 |
| `NOTION_DS`, `PARTNER_DS` | 노션 계약서 DB와 파트너 DB의 data source ID |
| `PARTNER_FIELDS` | 파트너 DB에서 계약서로 채울 속성. 이름과 선택지가 노션 DB와 글자까지 똑같아야 해요. 노션에서 속성이나 선택지를 바꾸면 여기도 바꾸고 다시 빌드하세요 |
| `PARTNER_RELATION`, `CONTRACT_RELATION`, `CONTRACT_TITLE` | 두 DB를 잇는 relation 속성 이름과 계약서 DB의 제목 속성 이름 |
| `DEFAULT_CRITERIA` | 검토 기준표 기본값 |

### 테스트 (Node.js 18 이상)
```sh
cd tests && npm install
sh ../app/build.sh
OUR_AUTHORS="우리측작성자1,우리측작성자2" node smoke.js ../app/contract-review.html <Word 파일 폴더>   # 파일 이름 순서 = 버전 순서
node test-docx.js <Word 파일 폴더>
node make-pdf.js <Word 파일> out.pdf && node test-pdf.js out.pdf
```
테스트용 계약서는 저장소 밖 폴더에 두세요.

## 보안 메모

- 계약서 본문, 코멘트, 분석 결과는 사이트를 만든 회사 claude.ai 조직의 저장소에 저장돼요.
- 노션 연동은 버튼을 누른 사람의 노션 권한으로 동작하고, 노션 토큰은 페이지에 노출되지 않아요.
- 이 저장소는 공개 저장소예요. 계약서 원본, `config.local.js`, 실제 업체명이 들어간 파일은 올리지 마세요.
